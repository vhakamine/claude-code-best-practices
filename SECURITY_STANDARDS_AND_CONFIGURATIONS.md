# Security Standards and Configurations Applied

This document outlines the security best practices applied to this repository for secure development with Claude Code (and general development).

## Applied Standards

1. **GitHub Security Best Practices** - Following GitHub's own recommendations for securing repositories.
2. **OWASP ASVS** - Application Security Verification Standard principles where applicable.
3. **Contributor Covenant** - For community conduct and inclusivity.
4. **Semantic Versioning** - For release management.
5. **Keep a Changelog** - For documenting changes.

## Configuration Files and Their Purpose

### `.github/SECURITY.md`
- **Purpose**: Defines the security policy for the project, including how to report vulnerabilities, supported versions, and scope.
- **Events Supported**: N/A (informational)
- **How It Works**: GitHub displays a "Security" tab on the repository, and this file's content is shown there. It also enables the "Report a vulnerability" button.

### `.github/CODE_OF_CONDUCT.md`
- **Purpose**: Sets expectations for community behavior to ensure a welcoming and inclusive environment.
- **Events Supported**: N/A (informational)
- **How It Works**: GitHub displays this file when contributors open issues or pull requests, and it can be linked in the README.

### `.github/CONTRIBUTING.md`
- **Purpose**: Provides guidelines for contributing to the project, including coding style, pull request process, and bug reporting.
- **Events Supported**: N/A (informational)
- **How It Works**: GitHub prompts contributors to read this file when opening a pull request.

### `.github/dependabot.yml`
- **Purpose**: Configures Dependabot to automatically create pull requests for dependency updates.
- **Events Supported**: 
  - `schedule`: Runs on a set interval (daily in this configuration)
- **How It Works**: 
  - Monitors the specified package ecosystems (GitHub Actions, Pip, NPM)
  - When updates are available, Creates pull requests to update dependencies
  - Can be configured to ignore certain dependencies or versions

### `.github/workflows/codeql-analysis.yml`
- **Purpose**: Sets up CodeQL analysis to automatically detect security vulnerabilities in the codebase.
- **Events Supported**:
  - `push`: On pushes to main and develop branches
  - `pull_request`: On pull requests targeting main and develop branches
  - `schedule`: Weekly on Mondays at 12:00 UTC
- **How It Works**:
  - On trigger, checks out the repository
  - Initializes CodeQL for the specified languages (Python and JavaScript/TypeScript)
  - Attempts to autobuild the project (if a build step is needed)
  - Runs CodeQL analysis to find security vulnerabilities
  - Uploads results as SARIF files to the Security tab, where they appear as alerts

## Additional Security Considerations for Claude Code Development

When using Claude Code for development, consider the following:

1. **Prompt Injection Protection**: Ensure that any user input passed to Claude Code is sanitized to prevent prompt injection attacks.
2. **API Key Security**: Never commit Claude Code API keys or any other secrets to the repository. Use GitHub Secrets for CI/CD.
3. **Generated Code Review**: Always review code generated by Claude Code for security vulnerabilities, as it may inadvertently introduce flaws.
4. **Dependency Scanning**: The CodeQL and Dependabot workflows help catch vulnerabilities in both your code and dependencies.
5. **Least Privilege**: When granting Claude Code access to repositories, use fine-grained tokens with only the necessary permissions.

## Verification of Configurations

To verify that these configurations are working:

1. **SECURITY.md**: Visit the repository's "Security" tab on GitHub.
2. **Dependabot**: Check the "Dependabot" tab under "Insights" or look for Dependabot pull requests.
3. **CodeQL**: After a workflow run, check the "Security" tab for code scanning alerts.
4. **Community Files**: When opening an issue or pull request, GitHub will show links to CONTRIBUTING.md and CODE_OF_CONDUCT.md.

## Maintenance

- Review the security policy quarterly.
- Update the Dependabot configuration if new package ecosystems are added.
- Monitor CodeQL alerts and address them promptly.
- Keep the contributing guidelines up to date with the development process.
